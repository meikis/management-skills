# 任务派发检查器（task-dispatch-checker）

按"五清楚工作法"自检派活内容，逐条标出缺失项，并生成可直接复制发送的派活话术。

## 对应培训模块

五清楚工作法 · 目标不清晰就拿不到正确结果（方法层）

## 触发条件

用户要给下属/同事派活、写任务说明、交办工作。触发词：`派活` `派任务` `布置任务` `安排工作` `写任务说明` `分派` `交办` `五清楚`

## 五清楚检查项

| # | 清楚项 | 检查问题 | 常见缺失 |
|---|--------|----------|----------|
| 1 | 想清楚 | 结果定义与可验收标准是什么？ | 只说动作不说结果，如"整理一下资料" |
| 2 | 问清楚 | 现场条件/资源/障碍确认过吗？执行人理解一致吗？ | 单向下达不确认理解 |
| 3 | 说清楚 | 时间、标准、边界都说了吗？ | 没说截止时间、没说做到什么程度 |
| 4 | 写清楚 | 有文字留痕吗？关键条款写下来了吗？ | 口头交办无凭据 |
| 5 | 做清楚 | 有跟踪节点吗？谁检查、何时检查？ | 派完不管，到期才问 |

**结果定义用名词不用动词**——"优化流程"是动词（不可验收），"交一份流程优化方案文档"是名词（可验收）。

## 输出物

1. 五清楚逐项检查结果（✅/❌/⚠️ + 原文依据）
2. 可直接发送的派活话术（任务/交付物/责任人/截止/资源/边界/超期处理）
3. 一行总结：完成度 + 最大风险点

## 派活话术模板

```
【任务】<一句话结果定义，动词+可验收结果>
【交付物】<文件/实物/汇报，验收标准：XXX>
【责任人】<姓名，一对一，禁止"大家/我们">
【截止】<YYYY-MM-DD HH:MM，含中途汇报节点>
【资源】<给什么支持：权限/人/钱/信息>
【边界】<不能动的红线、需请示的情形>
【超期/异常】<提前多久预警、向谁报>
```

## 示例

输入："让小张把车间那批探伤报告整理一下，尽快。"

输出：检查结果 0/5（"整理一下"无结果定义、无截止、无标准）→ 补全后的派活话术：

```
【任务】完成 9 月批次探伤报告电子归档并输出清单
【交付物】归档文件夹（按"日期-工件编号"命名）+ 清单 Excel，抽查 5 份零错漏
【责任人】张XX（一对一，禁止"我们/大家"）
【截止】10-13 17:00 前，10-12 12:00 前发我进度截图
【资源】共享盘归档权限已开；缺原始记录找王工
【边界】不合格报告单独放"待处理"文件夹，不得混入
【超期/异常】当天 12:00 未过半提前电话报我
```

## 踩坑提醒

1. "你看着办"是最危险的派活——等于放弃了结果定义权
2. 一个人派活多个人接——必须指定唯一负责人，否则责任稀释
3. 只说不写——三天后双方记忆出现偏差，无法追溯
4. 不设中间检查点——等截止日才发现方向全偏，来不及救

## 硬规则

- 责任人只能是一个名字，出现"我们/大家/相关部门"必须改成具体人（责任稀释定律）。
- 即使用户说"随便派一下"，也走完检查流程，可缩短输出但不省略检查步骤。
